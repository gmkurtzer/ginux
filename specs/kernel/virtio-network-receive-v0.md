# Virtio Network Receive v0

**Status:** One confined ARP request/reply exchange is verified on QEMU Q35.

## Purpose

This contract proves the first bounded receive operation through the native
virtio-net path. A packet generated by the device's restricted QEMU user
backend must enter an explicitly published, device-writable buffer and complete
through the dedicated receive MSI-X route while VT-d limits DMA to one page.

## Feature and buffer contract

The exact network feature set now includes `VIRTIO_NET_F_MRG_RXBUF`. This fixes
the modern virtio-net header at 12 bytes and requires the receive header to
report the number of buffers used. The bootstrap path publishes exactly one
1535-byte descriptor in queue 0 with only `VIRTQ_DESC_F_WRITE`; the buffer is
large enough for the 12-byte header and one ordinary 1514-byte Ethernet frame.
The byte before the buffer and the excluded final byte are distinct canaries.

Queue 1 contains a separate device-readable descriptor with a zeroed 12-byte
header and one padded 60-byte ARP request. It asks the restricted QEMU gateway
at `10.0.2.2` for its MAC using the pinned guest identity
`52:54:00:12:34:56` and `10.0.2.15`.

## Interrupt ordering

Both descriptors and available entries are published before `DRIVER_OK` and
before bus mastering is enabled. RX table entry 0 remains masked while TX
entry 1 is unmasked. The kernel notifies RX first and TX second, then requires
exactly one vector-35 interrupt and TX used-ring completion. It masks TX,
clears the one-shot interrupt state, unmasks RX, and requires exactly one
vector-34 interrupt. A receive completion that arrived while masked is
delivered through MSI-X pending state when entry 0 becomes unmasked.

## Reply validation

The receive used ring must advance exactly once with descriptor ID zero and a
length bounded by the published descriptor. The device must not report failure
or reset-needed state. The kernel requires:

- zero non-offload header fields and `num_buffers == 1`;
- destination MAC `52:54:00:12:34:56`;
- source MAC `52:55:0a:00:02:02`;
- Ethernet type ARP;
- Ethernet/IPv4 ARP geometry and reply operation;
- sender address `52:55:0a:00:02:02` / `10.0.2.2`;
- target address `52:54:00:12:34:56` / `10.0.2.15`; and
- unchanged RX and TX boundary canaries.

Ethernet padding after the required ARP fields may vary but remains inside the
used length and descriptor bound.

## Teardown and limits

The kernel function-masks MSI-X, masks both entries, disables MSI-X, revokes
bus mastering, resets the device, revokes PCI decoding, and retires both IDT
routes before VT-d or DMA leases are retired. Every post-installation failure
uses the same teardown.

This is a serialized bootstrap exchange, not a network stack. It has one RX
buffer, one request type, fixed QEMU addresses, no retry or timeout injection,
no fragmented receive chain, and no native-service delegation. Protocol state,
general packet queues, failure recovery, and container networking remain later
M6 work.
