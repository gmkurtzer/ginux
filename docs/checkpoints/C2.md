# C2 Verification: Runtime Domain Lifecycle

**Implementation status:** Complete; awaiting human verification.

## Capability

The signed measured-root profile authenticates the available Linux fixture but
creates no workload domain. At boot, `status` reports `domains: 0 configured`.
Create and configure a domain (Linux is the default personality):

```text
domain new default
domain set default image=embedded://minimal-system-v0
domain start default
```

Creation defaults to `init=/sbin/init`, `cpu=1`, `memory-mib=128`, and
`autostart=false`. Personality and image are intentionally required before
start. Override one or more settings when needed, for example:

```text
domain set default image=embedded://minimal-system-v0 cpu=1 memory-mib=128 autostart=true
```

The defaults are not fixed limits. CPU accepts any nonzero 16-bit count and
memory accepts any nonzero 64-bit MiB value.

The command accepts any number of `FIELD=VALUE` assignments that fit on the
command line. The earlier single-setting `domain set NAME FIELD VALUE`
spelling remains valid.

`default` is only an example operator-chosen name; it has no reserved meaning.
The bounded runtime record is not persisted across host reboot. Its Linux
`/sbin/init` runs as PID 1 in its process view and
appears as PID 100 in the host `/proc` view. The ring-3 controller remains a
separate, resident host PID 1 with delegated inspection and lifecycle
authority; domain transitions suspend and resume it without relaunching it.

Lifecycle commands then include:

- `domain list` — show every configured domain and its state, personality,
  init path, CPU count, memory limit, network attachments, and autostart policy.
- `domain status default`
- `domain stop default`
- `domain start default`
- `domain restart default`
- `domain fail default`

Stop and injected-failure transitions terminate and clean up the running init
before returning control. Start and restart create a fresh measured init
instance. The injected failure is a controlled lifecycle failure transition,
not an arbitrary CPU fault.

## Automated verification

```sh
make test-c2
```

The gate verifies that no implicit domain exists, explicit creation and
configuration, readiness, host PID visibility, stop, restart, contained
failure, recovery, clean shutdown, and rejection of a predefined profile
domain.

## Human verification on macOS

```sh
make doctor
make run
```

At `ginux>`, run the creation commands above, `ps`, `ls /proc`, and each
`domain` command. Confirm that PID 100 is visible only while `default` is
running, failure does not panic
the host, and `domain start default` recovers it. Finish with `shutdown`.

## Boundary of this checkpoint

This is the pinned minimal Linux fixture, not Rocky Linux or systemd. It proves
the runtime-configured lifecycle and authority boundary. Persistent domain
configuration and complete per-domain networking (including
static and DHCP configuration), and the
Rocky compatibility work remain subsequent checkpoints.
