# C1 Verification: Interactive Unified Boot

**Implementation status:** Complete; awaiting human verification.

## Capability

The build produces one `build/esp/EFI/BOOT/BOOTX64.EFI`. It embeds and measures
the kernel, bootstrap proof, boot artifacts, and resident controller. The
controller is a freestanding Rust static PIE mapped W^X and executed in ring 3
with only a read/write console capability.

The kernel supplies a bounded line-input ABI but never parses controller
commands. The controller implements:

- `help` — list commands.
- `status` — report controller privilege, container count, and integrity state.
- `components` — display the embedded component catalog.
- `shutdown` — exit the controller and request clean firmware shutdown.

No container is started by the C1 controller.

## Automated verification

```sh
make test-c1
```

The test waits for the prompt, exercises every command plus the unknown-command
path, verifies the component and status output, rejects panic markers, and
requires clean QEMU shutdown.

## Human verification on macOS

```sh
make doctor
make run
```

Wait for `ginux>`, run all four commands, and confirm that `shutdown` returns to
the host shell. QEMU uses TCG on Apple Silicon by default. UTM remains an
optional frontend for the generated EFI system partition; KVM acceleration is
reserved for a later x86-64 Linux host.
