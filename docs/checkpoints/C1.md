# C1 Verification: Interactive Unified Boot

**Implementation status:** Complete; awaiting human verification.

## Capability

The build produces one `build/esp/EFI/BOOT/BOOTX64.EFI`. It embeds and measures
the kernel, bootstrap proof, boot artifacts, and resident controller. The
controller is a Rust static PIE mapped W^X and executed in ring 3 through the
Linux x86-64 syscall ABI.
It receives read/write console access plus independently attenuated read-only
measured-root and host-inspection capabilities; it has no host mutation
authority.

The controller reads stdin and writes stdout with Linux syscalls; the kernel
never parses controller commands. A reusable, allocation-free command-tree library performs
whitespace normalization, nested dispatch, argument-count validation, and
generated Cobra-style help and usage output.

Host management uses a versioned Linux device/ioctl UAPI rather than private
controller syscall numbers. The controller remains a bounded relative-only PIE. Its richer static
command metadata permits at most 64 validated relative relocations, while
other native services retain the stricter eight-relocation ceiling.

The controller implements:

- `help [COMMAND...]` — show generated root or nested command help.
- `status` — report controller privilege, container count, and integrity state.
- `components` — display the embedded component catalog.
- `ls [PATH]` — enumerate the actual embedded, signed measured-root image.
- `ls /proc` — enumerate the global host PID view.
- `ps` — enumerate `/proc` and read each PID's status record.
- `shutdown` — exit the controller and request clean firmware shutdown.

No container is started by the C1 controller.

## Automated verification

```sh
make test-c1
```

The test waits for the prompt, exercises every command plus the unknown-command
path, verifies `/proc/1`, `/proc/1/status`, PID 1 controller output, components,
and status, rejects panic markers, and requires clean QEMU shutdown.

## Human verification on macOS

```sh
make doctor
make run
```

Wait for `ginux>`, run the commands above, try `ls /etc`, and confirm that
`shutdown` returns to the host shell. QEMU uses TCG on Apple Silicon by default.
UTM remains an optional frontend for the generated EFI system partition; KVM
acceleration is reserved for a later x86-64 Linux host.
