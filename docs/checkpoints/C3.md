# C3 Verification: Alpine Shell Container

**Implementation status:** Runtime OCI pull and Alpine shell path operational.

## Runtime image input

C3 accepts an explicitly configured OCI image reference and init path. No image
is embedded in the EFI binary and no container receives an implicit image.

```text
configured: docker.io/library/alpine:latest
platform: linux/amd64
init: /bin/sh
```

Build and boot Ginux on macOS or Linux with one command:

```sh
make run
```

`make run` never downloads or embeds Alpine on the host. At runtime,
`container start` downloads a missing image through the isolated network
service. `make test-alpine` exercises that path and a real musl/BusyBox shell
transcript.

## Ingestion boundary

The runtime path resolves the configured reference over control-domain
DNS/TCP/TLS, obtains a scoped bearer token, parses the OCI index and manifest,
and streams the selected layer through transactional boot-local storage. It
verifies the compressed digest before publication, performs bounded gzip/tar
expansion, and atomically installs the rootfs. Failed or partial pulls never
become visible.

## Current execution boundary

The configured init and its ELF-declared interpreter are now accepted by a
separate bounded, libc-neutral relocatable-PIE planner. The downloaded Alpine image
exercises BusyBox and musl with their four load segments and modern
metadata while enforcing load-bias alignment, W^X, mapped-page separation,
interpreter identity, image page quotas, and non-overlapping main/interpreter
address ranges. Invalid bases, interpreter substitutions, and overlapping
layouts are rejected.

The kernel maps the image's executable and interpreter pages through a dedicated,
scrubbed runtime extent, builds the Linux initial stack and auxiliary vector,
starts the unmodified ELF-declared interpreter in ring 3, permits the libc to establish its
TLS base and RELRO protections, and connects standard input, output, and error
to the serial console. The automated transcript enters `/bin/sh`, executes a shell
builtin, and exits cleanly back to the controller. Alpine is never reported as
running through the synthetic C2 `/sbin/init` fixture.

Rootfs-backed file syscalls, external BusyBox applets, process creation, and
clean restart are exercised. Detach/reattach with retained logs, multi-layer
filesystem merging, and per-container networking remain C3 work.

## Required runtime interaction

The target operator flow is explicit:

```text
container new alpine
container set alpine image=alpine:latest init=/bin/sh
container start alpine --attach
```

The controller canonicalizes short Docker Hub names such as `alpine:latest` to
`docker.io/library/alpine:latest`. Start automatically pulls a missing image.
`container start NAME --attach` now connects the console until the init process
exits and then returns to `ginux>`. Detach/reattach with `Ctrl-]` and a retained,
bounded boot log remain later C3 work.

Container records, cached image objects, writable overlays, and temporary data
remain boot-local in C3. Persistent image/configuration storage is a later
checkpoint. A future configurable pre-init policy may run declarative YAML
scriptlets before `/sbin/init` for systemd images; it is not an implicit Alpine
default and is not part of the shell checkpoint.
