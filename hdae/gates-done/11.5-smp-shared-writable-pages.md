# Gate 11.5: SMP Shared-Writable-Page Correctness

## Goal

Linux threads sharing an address space can concurrently read, write, and use
atomic operations on writable user pages across runtime CPUs without a kernel
fault, stale mapping, lost page ownership, or permission bypass.

## Approved scope

- Turn the scaled two-vCPU sysbench memory failure into a deterministic,
  minimal SMP regression.
- Identify whether the failure originates in page-table publication, address
  space ownership, copy-on-write materialization, CPU-local runtime state, TLB
  invalidation, or another measured mechanism.
- Correct mapping and invalidation behavior for writable pages shared by Linux
  threads in the same process address space.
- Add bounded synchronization where required so page metadata and hardware
  translations agree across participating CPUs.
- Preserve existing user-page permissions, W^X, SMEP, SMAP, ownership, frame
  accounting, and fault-containment invariants.
- Validate two- and four-vCPU shared-memory and atomic-write behavior before
  allowing Gate 11's scaled benchmark matrix to resume.

## Non-goals

- Performance tuning beyond removing correctness-driven pathological behavior.
- A general virtual-memory subsystem rewrite.
- New mmap, file-backed sharing, process-shared memory, NUMA, or swap features
  not required to correct same-process Linux thread mappings.
- Weakening page permissions, disabling hardware protections, or treating the
  fault as an expected benchmark limitation.
- Completing or interpreting the benchmark matrix; that remains Gate 11.

## Acceptance criteria

- A deterministic pre-fix test reproduces the scaled fault or its minimized
  underlying shared-page inconsistency under two vCPUs.
- Two Linux threads on different runtime CPUs can repeatedly perform ordinary
  and locked writes to the same writable user page and observe the expected
  final value without a user fault, kernel panic, stale translation, or hang.
- The same regression passes with four vCPUs and four participating threads.
- Read-only and non-executable page protections remain enforced; no test or fix
  grants broader access than the Linux mapping requests.
- Mapping teardown, frame accounting, and TLB invalidation leave no stale CPU
  access or leaked owned frame.
- The previously failing two-vCPU/two-thread sysbench memory workload completes
  at least three consecutive samples.
- `make check`, `make architecture-check`, `make test-smp`, and the focused
  private-futex regression still pass.
- Every test QEMU process is reaped and the benchmark volume is not left open.

## Decisions and limitations

- This is an inserted correctness gate. Gate 11's completed fixed-thread data
  remains valid and its scaled matrix stays paused until this gate passes.
- The gate is intentionally phrased around observable coherence and permission
  properties rather than assuming page-table publication or TLB invalidation
  is the root cause.
- Runtime mapping publication, replacement, permission changes, reservation,
  materialization, and removal now perform a serialized NMI-based invalidation
  on every online CPU plus local invalidation before success is published.
  Failed shootdown rolls the leaf back and fails closed.
- The fault path retains a permission-preserving local refresh as defense in
  depth. It retries only a present, user-accessible, live owned leaf that
  already grants the exact attempted access; it cannot add write or execute
  permission.
- CPUs running another address space may invalidate the same virtual address;
  that is harmless. A later CR3 activation supplies the required context
  flush for the target root.
- Any diagnosis requiring a general memory-manager redesign, weakened security
  invariant, or materially broader Linux sharing semantics returns to the
  human for a new scope decision.
