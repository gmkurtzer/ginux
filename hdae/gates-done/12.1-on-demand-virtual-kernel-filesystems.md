# On-demand virtual kernel filesystems

## Source

Human discovery that the native runtime materializes synthetic `/proc` and
`/sys` entries in the instance root rather than serving a true virtual,
memory-backed filesystem.

## Goal

Make `/proc` and `/sys` fully Ginux-owned virtual filesystems whose nodes,
directory entries, metadata, links, and contents are generated in memory on
demand from current instance state, with no procfs or sysfs files persisted in
the instance root.

## Approved scope

- Remove disk materialization and refresh of `/proc` and `/sys`.
- Route path lookup, open, directory enumeration, metadata, links, reads,
  bounded permitted writes, descriptor duplication, offsets, and closure for
  virtual kernel nodes through Ginux-owned in-memory objects.
- Generate process entries only for currently live virtual tasks and generate
  global values from current instance state when read.
- Preserve `/proc/self`, virtual identities, configured visibility, cgroup
  integration, systemd compatibility, `ps`, `top`, and proc/sys policy.
- Fail closed for unsupported virtual-node operations without consulting a host
  procfs or sysfs path.
- Add deterministic leakage, lifecycle, enumeration, and compatibility tests.

## Non-goals

- Passing through host `/proc` or `/sys`.
- Implementing every Linux procfs or sysfs node.
- Persisting virtual kernel nodes or their generated contents across starts.
- Changing the portable contract syntax or host networking model.

## Acceptance criteria

- The instance root contains no persisted files or directories beneath `proc`
  or `sys`; virtual nodes exist only through Ginux-mediated access.
- Opening or enumerating `/proc` and `/sys` generates current nodes and contents
  on demand without creating backing paths.
- `/proc` lists only live virtual PIDs, removes exited tasks immediately, and
  never exposes a host PID or unrelated host state.
- `ls -l /proc`, `ls -l /sys`, `ps -ef`, and a bounded `top` refresh complete
  without `ENOSYS`, stale entries, or host ownership leakage.
- Virtual metadata reports instance credentials and expected procfs/sysfs file
  types and permissions independently of host backing metadata.
- Existing systemd, contract, lifecycle, process, and performance-path
  regressions remain passing.

## Evidence

- Initial reproduction: `ls -l /proc` printed stale virtual PID directories and
  `Function not implemented`.
- Source inspection found `prepare_root` creating proc/sys backing trees and
  `native_proc_refresh_*` rewriting them before opens. `native_proc_remove`
  omitted `statm`, preventing stale PID directories from being removed.
- `make check` -> strict formatting and lint passed.
- `ROCKY_SSH_PORT=22510 make test-kernel-views` -> six component tests and the
  Rocky host-isolation fixture passed.
- `ROCKY_SSH_PORT=22511 make test-process` -> thirteen process component tests
  and the native Rocky process fixture passed.
- `ROCKY_SSH_PORT=22513 make test-systemd` -> cold, warm, repeated, failed-DNF,
  configured-startup-failure, and controlled-shutdown paths passed.
- `ROCKY_SSH_PORT=22515 make test` -> the complete component and Rocky QEMU
  aggregate regression suite passed.
- `ROCKY_SSH_PORT=22514 make demo-gate-12.1` -> `ls`, `ps`, `top`, live-task
  churn, virtual metadata, empty backing mountpoints, multi-user boot, and
  controlled shutdown passed.

## Decisions and limitations

- Host `/proc/<host-pid>` may be sampled internally for a managed tracee's
  scheduling and memory counters, but raw host paths, nodes, identifiers, and
  directory contents are never exposed to the instance.
- The virtual filesystem is an application-kernel object model, not tmpfs,
  bind-mounted procfs/sysfs, FUSE, or disk staging.
- Unsupported nodes return a Linux-compatible error and remain absent.
