# Instance terminology migration

## Source

Human direction after accepting Gate 10: replace the active product term
`domain` with `instance` before redesigning contract configuration and UX.

## Goal

Present one consistent `instance` concept across the active Ginux CLI,
configuration, implementation, persistent state, audit output, tests, and
documentation, with no supported legacy `domain` interface.

## Approved scope

- Replace `ginux domain ...` with `ginux instance ...` across every active CLI
  and helper workflow.
- Replace the `[domain]` TOML table and active schema/API terminology with
  `[instance]` and instance-named types, fields, crates, modules, fixtures, and
  examples where the term identifies the Ginux isolation unit.
- Rename active persistent paths from `/var/lib/ginux/domains` to
  `/var/lib/ginux/instances`, including lifecycle status, roots, caches, helper
  arguments, and cleanup behavior.
- Rename active audit fields, markers, logs, scripts, targets, configuration
  filenames, and user-facing documentation to `instance` terminology.
- Preserve technical uses of “domain” that do not name a Ginux instance, such
  as DNS domain names, Unix socket domains, protection domains, or external
  source terminology.
- Add deterministic stale-term checks over active product surfaces.
- Preserve the accepted behavior and security invariants of Gates 1 through 10.

## Non-goals

- Backward-compatible `domain` CLI aliases, `[domain]` parsing, or migration of
  existing `/var/lib/ginux/domains` state; this is an intentional clean break.
- Editing locked records under `hdae/gates-done/` or rewriting Git history.
- Changing contract semantics, instance behavior, or the underlying isolation
  architecture.
- Implementing the Gate 10.5 configuration and UX redesign.

## Acceptance criteria

- `ginux instance create/list/start/status/attach/stop` provides the accepted
  lifecycle; `ginux domain` is rejected as an unknown command.
- Active instance TOML uses `[instance]`; `[domain]` is rejected before launch.
- Runtime state is stored beneath `/var/lib/ginux/instances`; active code and
  tests do not create `/var/lib/ginux/domains`.
- User-facing output and structured audit identify an `instance`, not a Ginux
  `domain`.
- Active Rust package, module, type, field, function, script, fixture,
  configuration, and documentation names consistently use `instance` when
  referring to the isolation unit.
- A bounded stale-term check rejects reintroduction on defined active surfaces
  while excluding locked history and legitimate external technical meanings.
- Gate 10 contract behavior, Rocky systemd boot, network controls, hooks,
  lifecycle, and aggregate regressions remain passing.
- `make demo-gate-10.25` exercises the human-visible instance lifecycle and
  cleanly returns to the Rocky host.

## Decisions and limitations

- The migration is deliberately breaking because the project is still a
  research prototype and maintaining two vocabularies would make the upcoming
  UX redesign harder to understand and test.
- Locked historical gate records retain the terminology under which their work
  was reviewed and accepted.
