# Unified repository transition

## Goal

Make the userspace-kernel implementation the next Ginux development line while
preserving the complete standalone bootable-kernel history as an immutable,
discoverable historical line.

## Approved scope

- Preserve the final standalone-kernel `main` commit `4d4a53bb` as branch
  `bootable-kernel` and annotated tag `bootable-kernel-final`.
- Base `codex/userspace-transition` on the accepted `ginux-us/main` merge
  commit `2306c2e`.
- Join the standalone-kernel history as a second parent without replacing any
  userspace-kernel source files.
- Update project identity, repository links, transition documentation, and the
  HDAE checkpoint for the unified repository.
- Verify the userspace-kernel tree and its deterministic test suite before
  publishing a pull request against `main`.

## Non-goals

- Merge or push directly to `main`.
- Delete, rewrite, or archive either repository or either historical line.
- Implement Gate 9 or change userspace-kernel behavior.
- Import generated paper/PDF artifacts left untracked in the working tree.
- Continue development of the standalone bootable kernel.

## Acceptance criteria

- `bootable-kernel` and `bootable-kernel-final` resolve to `4d4a53bb` locally
  and on `origin`.
- The transition head descends from both `2306c2e` and `4d4a53bb`.
- Application source matches accepted `ginux-us/main`; only approved
  transition documentation and metadata differ.
- README and HDAE records describe Ginux as the active userspace kernel and
  point to the preserved standalone-kernel branch and tag.
- Deterministic formatting, lint, build, and test targets pass from the unified
  tree.
- A pull request targets current `main`; the agent does not merge it.

## Verification plan

- `git merge-base --is-ancestor 2306c2e HEAD` and
  `git merge-base --is-ancestor 4d4a53bb HEAD` -> both exit zero.
- `git rev-parse bootable-kernel bootable-kernel-final` -> both resolve to
  `4d4a53bb`.
- Source comparison against `ginux-us/main` excluding approved transition
  documentation -> no differences.
- `make check` -> exits zero.
- `make test` -> exits zero without network access.
- Remote ref and pull-request inspection -> historical refs exist and the
  transition PR targets `main`.

## Evidence

- `git fetch --prune origin` in both repositories -> Ginux remained at
  `4d4a53bb`; `ginux-us/main` advanced to `2306c2e`.
- GitHub inspection on 2026-11-04 -> both repositories have zero open pull
  requests and zero open issues.
- `git merge-base --is-ancestor b262f7f origin/main` in `ginux-us` -> exited
  zero, proving Gate 8 is included in merge commit `2306c2e`.

## Decisions and limitations

- The histories are joined with the `ours` merge strategy so Git records both
  lineages while the accepted userspace tree remains authoritative.
- Current Ginux `main` remains unchanged until the human reviews and merges the
  transition pull request.
- The separate `ginux-us` repository remains available until a later explicit
  archival decision.

## Delivery strategy

- Working branch: `codex/userspace-transition`
- Intended base: current `main` at `4d4a53bb`
- Pull request: intended; never merge without explicit authorization
- Planned commits: record transition gate and Gate 8 acceptance; join
  histories; update unified project documentation; record verification
- Actual commits: pending

## Review policy and outcome

Human checkpoint. The history transition changes the project's primary
development line and public repository identity. Stop after opening the pull
request so the human can inspect the ancestry, tree, documentation, and test
evidence before merging.
