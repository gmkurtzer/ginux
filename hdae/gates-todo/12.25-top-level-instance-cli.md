# Top-level instance CLI

## Source

Human review of the instance-management UX after Gate 12.

## Goal

Keep “instance” as the object name while removing the redundant `instance`
command group, and give top-level Ginux commands clear create, import, edit,
export, configuration, and lifecycle semantics.

## Approved scope

- Replace `ginux instance <command>` with `ginux <command>`.
- Make `ginux create NAME` create a default self-contained instance recipe and
  accept repeatable deployment/configuration flags.
- Make `ginux import NAME FILE` create or atomically replace an instance from a
  recipe while preserving the separation between recipe and deployment state.
- Provide `ginux set NAME`, `ginux edit NAME`, and `ginux export NAME`.
- Move list, start, attach, status, stop, lock, and unlock to the top level.
- Remove the old command shape without aliases and update examples, tests,
  help, and active documentation.

## Non-goals

- Renaming the instance concept or its persisted directories.
- Changing contract enforcement, virtual filesystems, or networking behavior.
- Implementing contract maintenance state; that belongs to Gate 12.5.

## Acceptance criteria

- `ginux create NAME` creates a valid instance from documented defaults without
  requiring a recipe file.
- `ginux import NAME FILE` creates or atomically replaces an instance; invalid
  input leaves prior state unchanged.
- `set`, `edit`, and `export` operate on the portable recipe and deployment
  state without silently mixing their ownership.
- Lifecycle and inspection commands work at top level and the removed
  `ginux instance` shape fails with concise help.
- Existing instance data remains readable without directory migration.
- Active examples, help, and tests contain no obsolete command shape.

## Decisions and limitations

- Top-level command names are intentionally concise because every managed
  object in this release is an instance.
- `edit` may use `$VISUAL`/`$EDITOR` with a safe fallback, but must validate and
  commit atomically after the editor exits.
- The internal runtime fixture command named `instance` remains deliberately;
  it is not exposed by the operator controller and is required by lower-level
  launch tests.
