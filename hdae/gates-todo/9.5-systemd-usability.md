# Systemd usability and operator lifecycle

## Source

Human testing of Gate 9 on 2026-11-05 exposed six usability and compatibility
defects before acceptance. The human approved this corrective Gate 9.5 and
authorized autonomous implementation and iteration through its final human
checkpoint.

## Goal

Make the general Rocky host workflow honest and usable: image acquisition
belongs to `ginux domain create`, runtime launch is configuration-driven, a
normal interactive shell has Linux-compatible job control and procfs, detached
domains can be reattached and detached without stopping, and the validated
systemd boot is free of Ginux-caused failures and warnings.

## Approved scope

- Remove OCI preparation and copying from `make run-host`.
- Make `ginux domain create` pull, digest-verify, assemble, and cache the
  configured OCI image on the persistent Rocky-host filesystem. A second
  domain and a later `make run-host` session using the same image must use that
  cache without reacquiring layers; domain definitions and status persist too.
- Report the current OCI object and real-time transfer progress while a cache
  miss downloads image layers.
- Derive the runtime executable and arguments from the normalized domain TOML;
  remove the trailing `systemd` launch selector from operator and test paths.
- Implement Linux-compatible process-group behavior required by Bash job
  control, including a parent calling `setpgid(child, child)`.
- Provide Ginux-owned procfs identity and the files and syscall behavior needed
  by ordinary process-inspection tools; do not mount or expose host `/proc`.
- Introduce persistent detached domain supervision and `domain attach`.
  `Ctrl-]` detaches the client while the domain continues running.
- Capture a fresh Rocky systemd boot, classify every failure and warning, fix
  those caused by Ginux compatibility, and turn the cleaned contract into a
  repeatable boot-log regression.
- Preserve every accepted interception, isolation, virtual-kernel-view,
  immutable-image, networking, update, and shutdown invariant.

## Non-goals

- Broadening the domain specification, interface selection, port policy,
  translation, volumes, hooks, or CLI override model; those remain Gate 9.75.
- Claiming complete procfs, Bash, systemd, or Linux ABI compatibility.
- Installing a container runtime or exposing the host's procfs to managed
  processes.
- Hiding legitimate missing-package or image-content diagnostics by weakening
  the ABI contract or filtering arbitrary console output.

## Acceptance criteria

1. `make run-host` boots a Rocky host without invoking OCI preparation,
   downloading an OCI image, assembling a rootfs, or copying a prepared domain
   image into the VM. A newly created host overlay is empty before the first
   domain create; a later host session reuses the prior overlay.
2. `ginux domain create rocky` acquires the image named by the domain
   configuration, verifies its pinned digest, creates the domain root, and
   records reusable cache content under the Rocky host's Ginux state directory.
   A cache miss displays the current layer and live transfer progress. Creating
   another domain from the same image, both in the same host session and after
   restarting `make run-host`, reports a cache hit and succeeds without image
   network access. Existing domain definitions remain available after restart.
3. The runtime launches `/sbin/init --system --unit=multi-user.target` from the
   normalized TOML without a trailing `systemd` argument. Missing or invalid
   init configuration fails before launch with one actionable diagnostic.
4. Interactive Bash commands, pipelines, foreground jobs, and background jobs
   no longer print `child setpgid ... Operation not permitted`; virtual process
   group queries and mutations return Linux-compatible results without exposing
   host process identities.
5. `/proc` identifies as procfs to managed software and provides the domain
   global and per-process data required by `ps -ef`, `cat /proc/self/status`,
   `cat /proc/self/cmdline`, and the existing systemd baseline. Host-only PIDs
   and host procfs content remain inaccessible.
6. Detached start is owned by a persistent per-domain supervisor. `ginux domain
   attach rocky` connects to the live console; typing `Ctrl-]` returns to the
   host shell without stopping systemd; reattachment works; stop and stale-state
   handling remain deterministic.
7. A fresh attached Rocky boot reaches the named multi-user login. Its captured
   console contains no unexpected Ginux-caused `Failed`, `failure`, `Operation
   not permitted`, unsupported-operation, or compatibility warning. Any
   remaining image-content diagnostic is explicitly classified and asserted by
   a narrow allowlist rather than silently discarded.
8. `make test-systemd`, the interactive host lifecycle test, the Gate 9.5
   command matrix, and `make test` all pass from fresh builds.
9. `make demo-gate-9.5` demonstrates host boot with an empty image cache,
   create-time acquisition and cache reuse, configuration-derived launch,
   login and proc/job-control checks, detached start, attach/detach/reattach,
   clean systemd diagnostics, and controlled shutdown.

## Decisions and limitations

- Bash uses `setpgid(child_pid, child_pid)` because its parent establishes a
  new process group for the forked job. Zero arguments are shorthand for the
  calling process and its PID; they are not the only valid Linux form.
- Procfs remains a Ginux-owned compatibility view. Passing the host proc mount
  through would violate the project boundary and is not an acceptable fix.
- `Ctrl-]` is the human-selected detach sequence.
- Boot-log cleanup must repair semantics, not suppress arbitrary output.
- Rocky systemd emits one accurate optional-feature diagnostic because Ginux
  does not expose a BPF LSM. Ginux does not falsely advertise that kernel
  feature; the exact line is narrowly allowlisted and every other matching
  warning or failure fails the console audit.
- Virtual `cgroup.procs` writes are mediated rather than retained as static
  file contents, so exited virtual tasks do not remain visible during shutdown.
  Full resource-controller semantics remain outside this corrective gate.
- The writable Rocky QCOW2 overlay is reused by `make run-host`, so verified
  OCI content, domain roots, configurations, and last status survive. Explicit
  `make clean` remains the reset mechanism and removes that overlay.
