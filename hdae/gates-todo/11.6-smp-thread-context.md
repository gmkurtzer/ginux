# Gate 11.6: SMP Linux Thread-Context Integrity

## Goal

Linux thread register state remains exact across SMP scheduling, syscall,
interrupt, NMI, blocking, wakeup, and resume paths, so the four-thread sysbench
yield workload cannot acquire a corrupted shared-counter pointer.

## Approved scope

- Reduce the scaled 4-vCPU/4-thread `sysbench threads` fault to a deterministic
  register-context regression.
- Capture every general register, CPU, thread slot, generation, and relevant
  scheduling transition at dispatch, suspend, wake, resume, and fault.
- Identify and correct the narrow context save/restore, ownership, generation,
  dispatch, interrupt, or NMI mechanism responsible for the corrupted address.
- Add two- and four-vCPU regressions that verify exact callee-saved,
  caller-saved, syscall-clobbered, stack, TLS, and atomic-counter state.
- Preserve thread isolation, generation checks, signal semantics, syscall ABI,
  NMI safety, and the Gate 11.5 translation-coherence fix.

## Non-goals

- Performance tuning or interpretation of the benchmark results.
- A general scheduler rewrite or support for more than the existing CPU limit.
- Hiding the fault, mapping the corrupted low address, or weakening page-zero
  and user-address protections.
- Completing Gate 11's measurement report.

- The 4-vCPU/4-thread sysbench thread-yield workload completes nine consecutive

## Evidence

- `make benchmark-topology-matrix` after Gate 11.5 -> scaled 2-vCPU/2-thread
  completed; scaled 4-vCPU/4-thread Linux and Ginux batch 1 completed. Ginux
  batch 2 faulted in `threads_1` at RIP `4283650`, CR2 `66050`, error 7, on
  bytes `240 73 255 3` (`lock inc [r11]`). The page-table and process registry
  both reported page `65536` unmapped.
- Full fault diagnostics showed live `r11=0x10206` while the same thread slot
  and generation retained saved `r11=0x8000ebb028` at the same RIP. The former
  is a flags value; the latter is the valid shared-counter pointer. This
  isolated the corruption to a cross-thread syscall return using SYSRET after
  an asynchronous interrupt save.
- Commit `5e3393e3` makes every scheduler-backed cross-thread syscall switch
  publish exact saved `rax`, `rcx`, and `r11` to the IRET epilogue. Same-thread
  syscall returns continue to use normal Linux SYSRET semantics. Remote CPU
  dispatch also consumes the exact saved general-register image.
- The verification boot now writes sentinel values to all 15 general
  registers, captures an interrupt context, prepares the cross-thread IRET
  return, verifies exact frame/RIP/RSP/RFLAGS/TLS/slot/generation state, then
  restores the original context. `make test-smp` passed at 1, 2, and 4 vCPUs
  plus both repeated 2-vCPU stress runs. Its existing protection probes reject
  absent, low, read-only-write, supervisor-only, and NX-execute access.
- `make test-rocky-smp-thread-context` completed nine 2-vCPU/2-thread and nine
  4-vCPU/4-thread sysbench thread-yield samples with status zero and no user
  fault, panic, context mismatch, stale generation, or hang.
- The exact original 4-vCPU/4-thread `cpu memory threads` sequence completed
  three fresh batches with three runs of each workload: all 27 markers were
  zero, including the second batch where the pre-fix fault occurred. No fault,
  panic, context mismatch, or stale generation appeared.
- `make check`, `make test-rocky-smp-futex`, and `make
  test-rocky-smp-shared-page` passed. `make check` includes the architecture
  checks. Exact-volume `lsof` inspection found no owner after the harnesses
  exited, and the harnesses reaped each QEMU child.
- Detailed evidence: [`docs/feedback-hardening/GATE-11.6-SMP-THREAD-CONTEXT.md`](../../docs/feedback-hardening/GATE-11.6-SMP-THREAD-CONTEXT.md).

## Decisions and limitations

- The unmapped low address must remain inaccessible. Mapping it would conceal
  corrupted execution state and violate the kernel's protection boundary.
- The timing-sensitive fault required full live and saved `r8`--`r11` plus
  CPU, slot, generation, and state diagnostics to distinguish correct storage
  from an incorrect return path.
- Work requiring a scheduler redesign or changed Linux ABI returns to the human
  as a new scope decision.
